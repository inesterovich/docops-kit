# ПЛАН разработки docops-kit

> Постоянный план по окнам. Меняется только при смене плана.
> Текущее состояние — `HANDOFF.md`. История окон — `docs/sessions/`. Идеи — `IDEAS.md`.
> Репозиторий: https://github.com/inesterovich/docops-kit · ветка `main`
> Рабочий каталог: `e:\Рабочие файлы\Илья\Программирование\docops-kit`

## Что строим

Набор шаблонов и проверок, переносящий документационные практики проекта `dance-autoreg`
в любой другой проект: карта владельцев документов, правила из ошибок (`R-*` ← `E-*`),
append-only журнал, линтер расхождений «документы ↔ факт», перенос состояния между окнами контекста.
Стек и наполнение целевого проекта на старте неизвестны — определяются интервью и пресетом группы.

Границы набора:

- **без CI/CD**: workflows, `.github/` и любые пайплайны — проектное решение; набор даёт команду проверки;
- **без зависимостей**: `init.js` и линтер — только встроенные модули Node;
- **без фактов целевых проектов**: версии, пороги, URL и ключи живут в проекте, не в наборе.

## Правила окна

0. **Проверить рабочую папку** (KIT-15): `pwd`, `git rev-parse --show-toplevel`, `git remote -v`;
   сверить с «Рабочий каталог» выше и с `HANDOFF.md`. Первая строка отчёта — рабочий каталог.
1. Начало окна: `HANDOFF.md` → раздел этого окна → последняя сессия в `docs/sessions/`.
   Большие документы проекта — только по карте чтения, целиком не читать.
2. Одно окно = один раздел ниже. Следующее окно не начинать «пока есть токены».
3. Всё, что нельзя потерять, пишется в файл в момент появления.
4. Решение для будущих проектов → `docs/decisions/ADR-NNNN-*.md`. Идея без решения → `IDEAS.md`.
5. Конец окна: `HANDOFF.md` → `docs/sessions/S-NN.md` → коммит → push. Окно без коммита не закрыто.
6. Ошибка инструмента или кода → `NOTES.md` в той же сессии.
7. В `HANDOFF.md` только ссылки на файлы, коммиты и вывод команд — без пересказов и «вроде работает».
8. Ветка одна — `main`. Тег — по версии набора (`v1.0.0` в окне 6).

## Бюджет окна

6–8 файлов и ≤ ~1500 строк нового текста/кода. `HANDOFF.md` ≤ 80 строк, сессия ≤ 150 строк.
Окна 4 (линтер) и 5 (`init.js`) при переполнении режутся на «код» и «фикстуры/прогоны».

## Риски нарезки

- Окно 4 может не влезть: тогда сначала 12 проверок документов, фикстуры — следующим окном.
- Окно 5 зависит от финального вида `core/`: если шаблоны меняются в окне 2, `init.js` не начинать раньше.
- Пресеты — черновики: до первого проекта каждой группы они не считаются проверенной практикой.

## Что запрещено в этом репозитории

- CI/CD любого вида (`.github/`, workflows, пайплайны) — `IDEAS.md` I-04.
- Полностековый пресет и «два проекта в одном репозитории» — I-01.
- Версии пакетов в пресетах — проверка №21.
- Зависимости в `init.js` и `checks/` — только `node:*`.
