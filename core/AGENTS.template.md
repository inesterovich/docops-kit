## 8. Сессии и перенос контекста

Окно контекста не бесконечно: всё, что нельзя потерять, пишется в файл в момент появления, а не «в конце».

**Шаг 0 каждого окна — проверка рабочей папки (KIT-15).** Первая строка отчёта — рабочий каталог:

```bash
pwd
git rev-parse --show-toplevel
git remote -v
```

Сверить с `{{WORKDIR}}` и с `HANDOFF.md`. Не совпало — остановиться и спросить, а не продолжать «раз похоже».

- **Начало окна:** `HANDOFF.md` → раздел текущего окна → последняя сессия в `docs/sessions/`.
- **Конец окна:** `HANDOFF.md` → `docs/sessions/S-NN.md` → коммит → push. Окно без коммита не закрыто.
- `HANDOFF.md` — срез, не история, ≤80 строк: ссылки на файлы, коммиты и вывод команд. Без пересказов и «вроде работает».
- `docs/sessions/S-NN.md` — история, ≤150 строк: что делали, чем проверили, чего не проверяли, отступления от плана.
- Ветка одна — `main`; тег — по версии проекта.
- Конец окна заканчивается промптом следующего окна — отдельный файл `docs/prompts/S-NN.md`, ≤20 строк, вставляется в новый чат без правок; ссылка на него — в `HANDOFF.md`.
- Ошибка инструмента или кода — запись в `NOTES.md` в той же сессии (см. §11).

## 9. Автоматика и тесты

Проверяется командой, а не прозой. Красный прогон блокирует коммит.

- Гейт документов: `{{GATE_COMMAND}}` — наличие документов профиля, относительные ссылки, незаполненные плейсхолдеры, порядок секций `CHANGELOG.md`, трассировка `E-*` ↔ `R-*`.
- CI/CD в набор не входит: где запускать гейт (локально, hook, pipeline) — решение проекта.
- Один прогон полного гейта в конце; итерации — по одному файлу, чтобы не ждать.
- Непроверенное перечисляется в отчёте разделом «чего не проверял», а не выдаётся за проверенное.

## 10. Процедуры

**Фича:** `SPEC.md` (поведение, контракты) → `README.md`, если видно пользователю → `CHANGELOG.md` `Unreleased` → тест → гейт.

**Документы:** гейт + `git diff` по коду пуст; факт правится у владельца (§1), остальные места ссылаются.

**Релиз:** поднять версию в проекте → `Unreleased` переименовать в секцию версии → гейт → один коммит и push → тег. CI и публикация — на усмотрение проекта.

**Аудит:** гейт + ручная сверка того, что гейт не покрывает (поведение, тексты, контракты). Итог — `NOTES.md` §Аудит; сводки пересчитываются по записям, а не по памяти.

**Расширение набора документов:** только по явному решению пользователя и с записью в `CHANGELOG.md`; профиль и его состав — в `profiles/` набора, в проекте — только то, что профиль требует.

## 11. Журнал ошибок (`NOTES.md`)

- Провал инструмента, ошибка кода или теста, расхождение документов, отступление от правил → запись в той же сессии, до коммита.
- Формат обязательный: сессия, категория, источник, что делал, как сломалось, почему, как починил, потери, правило, повтор.
- Append-only: старые записи не переписываются. Новый эпизод того же класса — **новая** запись с `Повтор: да (E-xxx)`, правило `R-*` переписывается.
- Трассировка в обе стороны обязательна: запись ссылается на `R-*`, правило цитирует `E-*`.
- `NOTES.md` не дублирует `CHANGELOG.md` (что изменилось) и `SPEC.md` (как должно быть). Правила живут только в §5.
- Перед задачей того же класса — прочитать последние три записи.

## 12. Запреты

- CI/CD любого вида в наборе: `.github/`, workflows, пайплайны. Где запускать гейт — проектное решение, набор даёт только команду.
- Версии пакетов в пресетах и профилях.
- Коммитить токены, пароли, приватные URL.
- Удалять или переписывать записи `NOTES.md`.
- Добавлять правило без записи `E-*` и запись без правила.
- Создавать новые документы, пока они не в карте §1.

## 13. Формат ответов в чате

- На русском.
- Первая строка отчёта — рабочий каталог, в котором выполнялась работа.
- Ссылайся на файлы и функции, а не «где-то в коде». Для изменений — diff или явное указание, что заменить.
- Не переписывай весь файл, если изменилась одна функция.
- В финальном отчёте — раздел «чего не проверял»: что осталось непроверенным и почему.
- «Синтаксис OK» и «тесты зелёные» — не доказательство, а цитата вывода команды.
