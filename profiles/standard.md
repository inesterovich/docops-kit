# Профиль `standard`

Рабочий профиль по умолчанию: `minimal` плюс описание поведения, правила проекта и решения.

## Когда выбирать

- поведение не помещается в `README.md` и меняется не каждый день;
- правила проекта уже выведены из ошибок, а не «на будущее»;
- решение, принятое однажды, должно объясняться через полгода.

## Что входит

Всё из [minimal](minimal.md), плюс:

| Документ | Роль |
|---|---|
| `SPEC.md` | поведение, контракты, схема данных, тесты — источник правды «как должно быть» |
| `rules/universal-rules.md` | правила набора `KIT-*`, общие для всех проектов; копируется как есть |
| `AGENTS.md` §5 | правила проекта `R-*`, каждое — из записи `NOTES.md` |
| `docs/decisions/ADR-NNNN-*.md` | решения, влияющие на будущие проекты: контекст, варианты, выбор, последствия |

## Команда-гейт

```bash
node checks/docs.test.js
```

Та же команда, что в `minimal`, но проверок больше: трассировка `E-*` ↔ `R-*` в обе стороны, наличие и уникальность ID `ADR`, соответствие `SPEC.md` карте владельцев, запрет дублей фактов между `README.md` и `SPEC.md`.

## Что запрещено

- Правила проекта вне `rules/` и вне §5 `AGENTS.md`; дублирование `KIT-*` в `AGENTS.md` — правка универсального правила идёт в `rules/`.
- ADR без последствий и без отвергнутых вариантов: «решили так» — не решение.
- CI/CD любого вида: workflows, `.github/`, пайплайны.
- Версии пакетов в пресетах и профилях.

Вниз, на `minimal`, — только явным решением пользователя: удаление `SPEC.md` и ADR теряет доказательства, которые уже собраны.
